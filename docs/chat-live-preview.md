# 聊天流内嵌工作区实况预览卡（genUI 形态，2026-11-19 移动适配裁决）

> 实现位置：`app/lib/widgets/chat_live_preview.dart`；挂载点
> `app/lib/widgets/chat_stream.dart:131-134`。引入提交 **46f1032**（chat-run
> live workspace preview as an inline genUI card in the chat stream，
> **replaces auto PiP**）。

## 1. 裁决与形态

chat agent 跑起来后，实况预览**直接长在聊天流的框里**（genUI 形态的内嵌工作区卡）
——**不是画中画浮窗**。此前「agent 运行自动弹出画中画」的行为已被本裁决取代：
预览不再是叠加在别处的第二块视口，而是聊天记录里的一张卡，随消息流滚动、可折叠。

## 2. 出现与消失条件

| 时机 | 行为 |
| --- | --- |
| `agentBusy && previewRender != null`（首轮实况帧就绪） | 卡片出现在聊天主面顶部（`chat_stream.dart:131-134`） |
| 运行结束（done / failed / 取消） | 卡片自动消失，**终稿回落画布与产物卡**——最终结果由画布与聊天流里的产物卡承载，卡片只服务运行过程 |
| 桌面窄栏（railMode） | **不挂**——桌面主面本身就是实况，窄栏里再放一块是重复 |

标题行常驻：呼吸圆点（运行中徽标）+「实况预览 · 正在构建工作区」+ 已成形屏数
（`previewRender.artboards.length`）。点击标题行折叠/展开；折叠态只留标题行，
把空间还给聊天记录。

## 3. 与桌面是同一条管线（不是新渲染路径）

卡体内嵌的就是桌面同一个 `Workspace`（`embedded: true` 模式，底层完全一致）。
实况数据源同一条 preview 管线：预览事件到达后 **700ms 合帧**去抖
（`app/lib/core/store.dart:3509-3521`，同一份渲染产物免重复渲染），到点才重渲染
并通知。因此：

- 手机/iPad 聊天优先壳看到的实况帧与桌面逐帧一致；
- 画布手势（拖拽/点选）在卡内直接可用——卡片不在聊天 ListView 里，
  没有嵌套滚动冲突；
- 不引入新的渲染代码路径，桌面侧的预览新鲜度治理原样生效。

## 4. 验收要点

- agent 运行中：聊天流顶部出现实况卡，屏数随生成增长；折叠展开正常。
- 运行结束：卡片消失，画布停在终稿，聊天流里有产物卡；不残留空白卡。
- 手机竖屏 / iPad 横屏：卡宽随面板自适应，展开高度 300 不溢出；触摸手势在卡内生效。
- 桌面窄栏：不出现该卡；桌面主面照常实况。

# NaN · 产品与设计交接书

> 给外部 UI/UX 设计师的交接文档。读完这份你能知道：**这个产品在做什么、什么是不可
> 动摇的、现在长什么样、哪里坏了、请你交付什么、怎么验收**。
>
> 版本：2026-11-26。代码事实源：仓库 `NoNDesign`（Flutter 客户端 + 纯 Dart 本地核心）。

---

## 1. 一句话

**输入一句话，得到一份产品需求设计文档，再得到一套完整可交互的原型。**

同一个底座还能做 **3D 场景 / 代码动画视频（含 3D 视频）/ 音乐编曲 / 带本地数据库的
「热应用」**。设计、3D、视频、音乐四个工作台是**同一个底座的四视图**，不是四个互相
独立的工具。

## 2. 核心理念：代码创造世界

这是方向与取舍的唯一事实源（`docs/vision.md`）：

> 人提出世界，Agent 写出世界的源代码；工作台让世界**可进入、可修改、可验证、可带走**。

推论（设计时要守住的东西）：

1. **产物是"世界"，不是"图片"**：一切以可运行的代码/数据为准，截图只是结果。
2. **可见即可改**：用户在画布/谱面/时间线上的每一次操作，都必须落到可验证的事实源上，
   不存在"只改了显示"。
3. **终态诚实**：没有做到的事不许显示成"已完成"；失败必须看得见。
4. **可带走**：产物要能导出、能脱离本机运行，不做平台锁定。

新功能先过"五问滤镜"（`docs/vision.md` §7）：它是否让世界更可进入/可修改/可验证/
可带走/更可信？答不上来就不做。

## 3. 用户与场景

| 用户 | 典型起点 | 想要的终点 |
| --- | --- | --- |
| 产品/设计师 | 一句想法 | 能点、能演示、能改的原型 + 需求文档 |
| 独立开发者 | 一个场景描述 | 可运行的交互页面/热应用，带本地数据 |
| 内容创作者 | 一段故事/歌 | 3D 视频、代码动画或可演奏乐谱 |
| 想要验证想法的人 | 模糊需求 | 立刻看到"做出来大概是什么样"，再迭代 |

关键体验指标（设计目标，非硬指标）：**从一句话到第一帧可见产物 ≤ 1 次交互停顿**；
任何 3 秒以上的操作必须有可见进度与可取消。

## 4. 产品结构

```
┌──────────────────────────────────────────────────────────────┐
│ 外层壳 WorkspaceChrome（所有工作台共用，设计师要统一的部分）      │
│  标题栏（项目下拉/命令条/主题/设置）                              │
│  左侧图标轨 / 主区 / 右侧 NaN 栏（聊天+检查） / 底部状态栏        │
├──────────────────────────────────────────────────────────────┤
│ 内容区（每个工作台**独立适配**，设计师要分别设计的部分）           │
│  设计：画板 + 图层 + 检查器（画布优先）                          │
│  3D  ：视口 + 大纲 + 检查器 + 视口控件（视口优先）                │
│  视频：导演台（剧本树/预览/检查器 + 时间线）                      │
│  音乐：项目列表 + 谱面（五线谱/卷帘）+ 检查器 + 运输条             │
│  3D视频：项目列表 + 预览 + 检查器 + 镜头时间线（复用视频规格）      │
│  热应用：内容区布局**冻结不动**（历史裁决）                        │
├──────────────────────────────────────────────────────────────┤
│ 全幅页面：Welcome 首页 / 作品集 / 播放                              │
└──────────────────────────────────────────────────────────────┘
```

产品裁决要点：

- **工作台切换 = 项目切换**：一个项目只属于一种工作台；项目内不再放工作台切换条。
- **右侧 NaN 栏只有两个 tab**：NaN（聊天+任务执行）/ 检查。
- **共享的只是外层壳**；内容区的交互姿态与布局必须**按工作台各自设计**，不允许把设计面
  的 252/348 面板几何套到 3D/视频/音乐上。
- **断点唯一来源**：`app/lib/core/workbench_layout.dart`（每个工作台自己的面板策略与宽度）。

## 5. 工程边界：设计师不需要实现，但**不能破坏**的 8 条

1. **单一事实源**：设计稿是 canonical `.mbt.md`；人类操作走 `apply_human_op_in`，Agent
   操作走 `apply_agent_op_in`。UI 不得绕过门直接改数据。
2. **Dart 不解释视觉语义**：渲染只消费引擎返回的 nodes/svg，本地 painter 只画选区/
   悬停/手柄等覆盖层。设计师提出的"界面里画出来的东西"必须能表达成数据或 op。
3. **引擎宿主只有一处**（`lib/core/engine/`），生产跑在离屏 WebView 里；不要把引擎
   调用搬到 UI isolate 或另起一套运行时。
4. **所有应用内 WebView 统一走 `webview_all`**；WebView 宿主的裁剪**只能是矩形或
   `ClipRRect`**——装饰容器 + `clipBehavior` 会生成任意路径 `ClipPath`，在 Linux
   WebKitGTK 上会**把 WebView 直接隐藏**（真机实测事故，见 AGENTS 已知限制）。
5. **能力缺失不得静默**：不可用时给出 `CapabilityAvailability.message`，原始诊断只进
   折叠的「技术详情」；禁止假按钮/假进度。
6. **用户可见文案受门禁约束**（`docs/copy-glossary.md` + `copy_guard_test.dart`）：
   不出现 Python/server/wasm/MoonViz/DDP/mbt/canonical/nonapp/ACP/engine/session_*/
   tool_*/JSONL/localhost/端口/构建代号；工具名必须经 `toolLabel()`。
7. **动效/配色/字号只能取令牌**：`NonMotion`（120/180/240ms, easeOutCubic）、`NonPalette`
   （唯一颜色源）、`NonType`/`NonSpace`/`NonRadius`（见 §7）。硬编码 hex 已清零，
   裸字号正在清零（有棘轮门禁，只许下降）。
8. **热应用工作台内容区布局冻结**（用户裁决 2026-11-24），其余工作台可重排。

## 6. 主题现状（重要：这正是要重新设计的部分之一）

- **深色**是当前默认主题（暗背景、低对比面板、品牌色 `#7C8CFF`）。
- **浅色 = Aqua**（用户裁决 2026-11-26：不新增第三套主题，浅色就是 Aqua）：
  细条纹窗口底 + 糖果凝胶主按钮（不透明水蓝渐变 + 上半球高光 + 内发光 + 细边线，
  **明确不是毛玻璃**）+ 红/黄/绿口香糖窗口控件 + 深色软阴影；凝胶上白字带轻微下投影，
  对比度 ≥ 4.5:1；键盘焦点必须有可见环；呼吸光晕在减少动效时完全静止。
- 实现集中在 `app/lib/widgets/aqua.dart` + `NonPalette.light`。
- **两套主题尚未贯通所有面板**——这是已知问题，见 §8。

## 7. 设计令牌（当前事实，设计师应在此基础上给规格）

| 类别 | 令牌 | 取值 |
| --- | --- | --- |
| 字号 | `NonType` | 10 / 11 / 12 / 13 / 15 / 18 / 22 / 34（第 10 档为可读性地板） |
| 行高 | `NonType` | 正文 1.45，说明 1.4 |
| 间距 | `NonSpace` | 2 / 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | `NonRadius` | 6（小控件）/ 10（面板）/ 14（大卡片） |
| 动效 | `NonMotion` | fast 120 / base 180 / slow 240ms，easeOutCubic |
| 颜色 | `NonPalette` | 深色与 Aqua 各一套；禁止新 hex |
| 组件 | `widgets/aqua.dart` | 凝胶按钮、条纹面、口香糖控件、窗口表面 |

> 设计师新增任何尺寸/字号/颜色，请给「令牌名 + 值 + 使用场景」，由工程加进令牌表；
> 不接受在界面里随手写数字。

## 8. 已知 UI 问题（**请把这 5 条当作这次设计的靶子**）

以下都是实测量化，不是感觉：

1. **字号不统一**：`lib/widgets` 里曾有 **884 处**硬编码 `fontSize`，横跨 16 个档位
   （10/10.5/11/11.5/12/12.5/13/14/15/16/17/18/22/34）。同一层级的标签在不同工作台
   大小不同。→ 令牌层已建立，正在逐文件迁移（棘轮门禁只许下降）。
2. **主题不一致**：深色与 Aqua 两套材质只覆盖了部分组件；同一个"主按钮"在设置面板、
   工作台工具条、对话框里形态不同；部分面板在浅色下仍是暗色时代的对比度假设。
3. **工作台内部太乱**：面板头部高度/内边距/字号在同一屏内不统一；边框一层套一层
   （外层容器 + 面板 + 卡片各一道）；信息层级不分明（标题、关键值、说明混在一起）。
4. **不跟窗口走**：大量固定尺寸/魔法数（面板宽、工具条高、卡片高）没走 `LayoutBuilder`
   或 `workbench_layout.dart` 规格；窗口放大缩小后出现留白失衡或溢出。
5. **卡顿/重绘**：全仓只有 4 处 `RepaintBoundary`；WebView 宿主与 painter 常被父级带动
   重绘；静态头部随 store 广播全量重建；列表未用 `itemExtent`。

## 9. 需要你交付什么

### 9.1 信息架构与布局（按工作台分别给）

- 每个工作台给 **窄 / 中 / 宽三档**（参考断点 900 / 1280 / 1600，可建议新值）：
  - 三档下**面板去留规则**（dock / sheet / hidden）与宽度；
  - 最小可用尺寸下"谁让位"（例：3D 先隐藏大纲，视频先收窄剧本树）；
  - 面板收起后的**入口**（不允许"面板没了且没有入口"的死路）。
- 共享外壳只给一份：标题栏 / 左轨 / 右 NaN 栏 / 状态栏 的高度、分区、密度。

### 9.2 组件规格

每个组件给：**形态（含材质）、尺寸、各状态（默认/hover/pressed/disabled/focus）、
键盘可达性、密度（常规/紧凑）**。至少覆盖：

按钮（主/次/危险/图标/分段）、输入与下拉、标签与徽标、面板头部、工具条、列表行、
树行、检查器行（键-值-编辑）、时间线刻度与播放头、谱面小节/音符、空态、错误态、
加载态、对话框、Toast、右键菜单、快捷键提示。

参考：`https://namethatui.com/` 的组件命名体系（macOS 分类含 Dock、Path Bar、
Status Bar、Toolbar 等）——用它统一我们内部的叫法，避免"那个条/那个块"。

### 9.3 主题规范

- 深色与 Aqua 各给一套完整映射（背景/面板/线/文字四级/品牌/语义色/强调），
  并给出**对比度表**（正文 ≥ 4.5:1，大字或非文本 ≥ 3:1）。
- 明确"哪些材质可以出现在哪"（例：Aqua 凝胶只用于主 CTA，不用于面板底）。

### 9.4 动效规范

进入/退出、状态切换、进度、播放头、脉冲。全部给时长与曲线，落在 `NonMotion` 三档内；
必须给 `prefers-reduced-motion` 的静态替代。

### 9.5 文案与状态

空态/错误/加载/禁用 四类，每类给"人话文案 + 可行动作"，不许出现内部技术词。

## 10. 怎么跑起来看 & 怎么验收

```bash
# 桌面客户端（真机外观）
cd app && flutter run -d linux          # macOS 用 -d macos

# 真 WebView 页面冒烟（音乐播放页 / 3D 视频预览页 / 3D 视口控件）
scripts/wf/run_webview_smoke.sh

# 工程门禁（改完必须绿）
cd app && flutter analyze --no-pub
LD_LIBRARY_PATH=~/.local/nan-dev/lib flutter test --no-pub
```

当前门禁基线：`analyze` 干净；全量测试 1698 通过 / 1 条既有环境失败
（容器 loopback 无法观测，已登记）；`flutter build linux --debug` 通过。

设计交付验收：把设计稿按上面 9.1–9.5 落到 `docs/` 下（架构图 + 三档布局 + 组件规格 +
主题表 + 动效表），并配一页"与现状差异清单"，工程按它分批实施。

## 12. 一句话提醒

**这个产品的主角是"作品"，不是"界面"。** 界面要让用户尽快看到自己的世界出现、并且
相信它真的可以被改、被执行、被带走。任何让"看起来完成"先于"真的完成"的设计，都不符合
这个产品的理念。

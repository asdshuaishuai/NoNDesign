# 愿景：代码创造世界

> 状态：**生效（2026-11-20 用户裁定）**。本文是产品愿景的唯一事实源；
> [plan-creative-workbench.md](plan-creative-workbench.md) 定施工，本文件定方向与取舍。
> 一句话：**NaN 是一个用代码创造世界的创意工作台。**

## 1. 愿景

**人提出世界，Agent 写出世界的源代码，工作台让世界可进入、可修改、可验证、可带走。**

「世界」不是比喻：一个产品界面、一个 3D 场景、一支动画短片、一首编曲，都是可运行的世界——
有事实源、有法则、有编译产物、有验收标准。工作台不是内容工厂，是**世界引擎**。

## 2. 世界即代码：四个工作台是同一底座的四视图

| 工作台 | 世界 | 事实源 | 编译产物 | 验证 |
| --- | --- | --- | --- | --- |
| 设计 | 产品世界 | canonical `.mbt.md` + DESIGN.md | 可交互原型 + 验证原型 | 引擎门 + 覆盖验证 |
| 3D | 空间世界 | `scene.json` | three.js 运行时场景 | 几何/材质/引用校验 |
| 视频 | 叙事世界 | `screenplay.json` | Phaser 引擎短片 | 镜头/台词/时长自检 |
| 音乐 | 声音世界 | `score.json` | Web Audio 播放页 | 乐谱校验器 |

四种世界共享同一组性质：**自包含、离线、可 diff、可 fork、可重编译**。
换一个工作台不是换一个产品，而是换一个世界的视图。

## 3. 七条原则

1. **代码是事实源，不是导出格式。** 生成物必须回到源码层可编辑；不可逆的生成物不算交付。
2. **世界必须可运行。** 不是效果图：能进入、能操作、能播放、能交互。
3. **世界必须可验证。** 每个世界有法则（schema / validator / gate）；「模型说完成了」不算数。
4. **世界必须可带走。** 自包含产物脱离 NaN 也能运行、播放、被审查；不拿锁死换留存。
5. **Agent 是世界作者，不是按钮。** 它写代码、改事实源、接受门禁；人类做导演、审查与取舍。
6. **强绑定强规范是世界法则。** 项目↔工作台、工作台↔事实源、Agent↔工具面、执行归属；
   每个模块四件套（schema、校验器、工具族、执行/结果双面）缺一不可。
7. **本地优先、确定性优先。** 离线、无端口、可重放；云是增强，不是前提。

## 4. 反愿景（明确不做）

- **不做抽卡式内容生成器**：一次生成、不可编辑、不可复现。
- **不做素材仓库 / 模板货架**：没有世界法则的模板只是皮肤。
- **不做通用低代码画布**：节点图不是目的，世界才是。
- **不做云端锁定的创作工具**：世界必须能带走。
- **不做「全能但全不精」的功能堆叠**：四个工作台共享底座，但各有清晰的深度边界
  （设计到验证原型、3D 到建模、视频到导演台、音乐到编曲）。

## 5. 用这个愿景读 2026-11-20 的全网调查

调查结论一句话：专业工具在拼**产物治理**，消费平台在拼**分发与模板**；真正的空白是
「交换标准之上的生成侧契约」（USD / OTIO / MusicXML / Design Tokens 解决了交换层，
缺可回写参数、跨层校验、确定性编译）。这正是「代码创造世界」的施工面：

| 调查发现 | 对愿景的含义 |
| --- | --- |
| 设计竞争转向「生成物可编辑/审查/交付」 | 我们更彻底：事实源级可编辑，验证原型是世界的验收面 |
| 3D 差距在管线最后一公里（重拓扑/绑定/材质） | 用 `scene.json` + 程序化图元把最后一公里变成代码问题 |
| 视频没有可移植、可版本化的剧本中间表示 | **最锋利的空白**：`screenplay.json` 编译、逐镜重渲染、可 diff、可成本预演 |
| 音乐输出音频/stems、编曲不可逆 | `score.json` 是少数以「可逆乐谱」为事实源的路线 |
| Skill 是无签名、无定价、无评测的裸文件夹 | 「世界技能」= 带 schema + validator + 工具族的可验证代码配方 |
| Agent 平台分水岭是执行可治理 | 强绑定 + 门禁 + 可回放，正好是治理 |
| chat + artifact 成为默认交互 | 我们的差异：artifact 是**可进入的世界**，不是预览图 |
| 本地优先的活法是「本地核心 + 可选云」 | WebView 引擎路线避免原生依赖税，保持世界可携带 |
| 中国市场的胜负手是分发 | 暂不拼分发，先做创作底座；导出与标准格式是后续分发策略 |
| 模板市场的本质是冷启动供给 | 世界即代码天然可 fork；模板应是「可运行世界的种子」 |

## 6. 成功判据（3–5 年）

1. 四个工作台的事实源都能被第三方工具读写（schema 公开、格式稳定、有迁移规则）。
2. 一个世界可以从 NaN 导出，在浏览器或引擎里独立运行。
3. 每个模块有确定性校验器，验收不依赖模型自述。
4. Agent 可以在一个世界内连续工作数小时，产出可 diff、可回滚的代码变更。
5. 用户能把一个世界 fork 成另一个世界（模板 / 社区的最小闭环）。

## 7. 决策滤镜（新功能/新模块先过五问）

1. 它让世界更**可编辑**，还是更不可编辑？
2. 它让世界更**可验证**，还是更靠感觉？
3. 它让世界更**可带走**，还是更锁定？
4. 它是在**写世界**，还是在堆素材？
5. 它配得上**强绑定强规范**吗（schema / validator / 工具族 / 双面）？

答不上来就不做。愿景不是扩张许可，是取舍依据。
